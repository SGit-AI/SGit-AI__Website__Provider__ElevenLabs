Multi-speaker dialogue

A question and an answer, in two voices, generated in one call so the pacing holds across the turn. Concatenating two separate generations does not give you this, and the difference is audible.

1 · The exchange

One request, several voices, consistent pacing across the turns — which is the thing you cannot get by generating each line separately and concatenating. A two-voice cut (a question and an answer) is one endpoint away from a single-narrator reel.

2 · The result

3 · Log

What this tests

POST /v1/text-to-dialogue takes inputs: [{ text, voice_id }, …] and renders the whole exchange in one request with consistent pacing vendor docs 5 Sep 2026. The /with-timestamps variant returns the same character-level alignment as ordinary speech, so everything the captions studio does works on a dialogue too.

For a single-narrator explainer this is one endpoint away rather than a rewrite, and it changes what a script can be: a rhetorical question that is actually asked by somebody else lands differently from one the narrator asks themselves.

What to listen for

  • The seam. Generate the same two lines separately, concatenate them by hand, and compare. If the single-call version does not sound more like a conversation, the endpoint is not earning its keep for your material.
  • Turn-taking pace. Real exchanges overlap slightly and vary their gaps; a model that leaves an identical pause after every turn sounds like a phone tree.
  • Whether the voices stay distinct when the text is technical and both speakers use the same vocabulary.
